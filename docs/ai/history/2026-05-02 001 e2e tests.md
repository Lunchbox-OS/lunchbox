# End-to-end test harness

## Summary

Added a new `shepherd-e2e` crate that boots the full shepherd stack against a real, headless Sway compositor and drives it through the HTTP management API and IPC socket. The harness is a private library (`publish = false`) plus an integration-test file under `tests/`. All test functions are gated with `#[ignore]` so a plain `cargo test --all-targets` skips them; CI runs them in a separate `e2e` job via `cargo test -p shepherd-e2e -- --include-ignored --test-threads=1`.

The original ask was for "a true test, including a proper Sway session" that is also runnable in CI. The harness intentionally avoids `MockHost`/SHEPHERD_MOCK_TIME — every test starts its own sway, its own shepherdd, and its own temp `XDG_RUNTIME_DIR`, then exercises real HTTP endpoints, real SSE frames, real IPC frames, and observes real `/proc` entries for the spawned activities.

## Scenarios covered

1. **Boot, health, clean shutdown** — `/api/v1/health` returns 200, IPC `Ping` round-trips, SIGTERM yields an exit status of `success`.
2. **Launch and stop via HTTP** — `POST /sessions { entry_id: "sleeper" }`, observe a `sleep` PID under `/proc`, `DELETE /sessions/current` returns 204, `sleep` PID disappears, `GET /sessions/current` returns `null`.
3. **Timeout** — launch the `ephemeral` entry (`max_run_seconds = 2`), open SSE, wait up to 15s for a `session_ended` event with `reason.type == "expired"`.
4. **Extend** — launch sleeper, `POST /sessions/current/extend { seconds: 600 }`, assert the deadline string moves forward.
5. **Daily override** — `PUT /overrides/always-on { availability: false }`, then `GET /entries/always-on` reports `enabled == false`. `DELETE /overrides/always-on` cleans up.
6. **Config reload** — rewrite the config file on disk, `POST /config/reload`, assert `GET /entries` reflects the new entry list.
7. **Auth** — when the harness is built with `auth_token("e2e-secret")`, an authenticated client gets 200 and an unauthenticated one gets 401.

## Design decisions

- **Real sway + real shepherdd, no mocks.** `MockHost` would not have caught real spawning, signal-handling, or HTTP-binding bugs. The wlroots headless backend (`WLR_BACKENDS=headless WLR_LIBINPUT_NO_DEVICES=1 WLR_RENDERER=pixman`) lets sway run inside a container with no GPU.
- **Hand-rolled HTTP/1.1 client** in `crates/shepherd-e2e/src/http.rs` rather than pulling in `reqwest`. The protocol surface is tiny (GET/POST/PUT/DELETE on localhost + chunked decoder + SSE frame parser) and avoiding TLS/native-TLS dependencies keeps build time and the dependency tree small.
- **Custom `IpcClient::connect`** is reused from `shepherd-ipc` rather than reimplemented, so the IPC test uses exactly the same protocol clients see in production.
- **Per-test temp `XDG_RUNTIME_DIR`** with mode `0700`, plus a per-test ephemeral TCP port for the management API. Each `TestHarness` is fully self-contained and can run sequentially without conflicting with other tests, system sway, or other shepherdd instances.
- **`#[ignore]` + `--test-threads=1`** because each test starts its own Sway and shepherdd; running them in parallel would cause `wayland-N` socket and PID-file races. This pattern is standard for "real-environment" integration tests.
- **`SHEPHERD_MOCK_TIME` is intentionally not used** — it's fixed at process startup and uses `MonotonicInstant`, so it cannot advance mid-test. Instead, the timeout test uses a real two-second `max_run_seconds` and an SSE wait of 15s, which is reliable under load.
- **Synchronous best-effort `Drop`** for the harness sends SIGTERM to all child processes and sleeps 500ms. The async `shutdown()` method is preferred (graceful SIGTERM with 3s wait, then SIGKILL); `Drop` is the safety net for panicking tests.
- **HTTP port allocated by binding `127.0.0.1:0`, then dropping the listener.** The standard "TOCTOU race but in practice fine" trick. Acceptable because each test uses a fresh port and the daemon binds with retry.
- **Workspace binaries located via `CARGO_MANIFEST_DIR`** (`<workspace>/target/<profile>/<name>`) rather than `CARGO_BIN_EXE_*`, which is only set for binaries declared in the same crate as the test. The harness errors clearly if the binary is missing ("run `cargo build` first").

## Key files

- `crates/shepherd-e2e/Cargo.toml` — library crate with `publish = false`. Depends on `shepherd-api`, `shepherd-ipc`, `shepherd-util`, `tempfile`, `nix`, `tokio`, `serde_json`, `tracing`.
- `crates/shepherd-e2e/src/lib.rs` — `TestHarness`, `HarnessBuilder`, `HarnessProcess`, `default_config_toml()`, `proc_inspect` module.
- `crates/shepherd-e2e/src/http.rs` — minimal HTTP/1.1 client with `HttpClient`, `HttpResponse`, `SseStream`.
- `crates/shepherd-e2e/tests/e2e.rs` — the seven `#[ignore]` test functions.
- `crates/shepherd-e2e/README.md` — usage notes.
- `Cargo.toml` — added `crates/shepherd-e2e` to `[workspace] members`.
- `scripts/deps/test.pkgs` — new package list (`sway`, `dbus-daemon`, `coreutils`).
- `scripts/lib/deps.sh` — added the `test` set; the `dev` set now unions `build + run + test + dev`.
- `.github/workflows/ci.yml` — new `e2e` job that installs build + run + test deps, builds the binaries, and runs `cargo test -p shepherd-e2e -- --include-ignored --test-threads=1` inside `ubuntu:25.10`.

## Running locally

```sh
./scripts/shepherd deps install run
./scripts/shepherd deps install test
./scripts/shepherd build
cargo test -p shepherd-e2e -- --include-ignored --test-threads=1
```

The full suite runs in ~4s on a developer machine (each test spends most of its wall time in the 100ms sway/shepherdd boot poll loop, plus ~2s for the timeout scenario).

## Caveats / future work

- The harness runs sway with `env_clear()` plus a small allowlist (PATH, HOME, USER, XDG_RUNTIME_DIR, WLR_*, XDG_SESSION_TYPE). If sway in CI ever gains a hard requirement on something else (e.g. `DBUS_SESSION_BUS_ADDRESS`), wrap the spawn in `dbus-run-session`.
- The launcher and HUD UIs can be spawned via `HarnessBuilder::spawn_launcher(true)` / `spawn_hud(true)` but no test currently exercises them — adding a test that drives the GTK UI through Wayland input events would require a much bigger virtual-keyboard plumbing setup.
- The activity stop test scans `/proc` for processes with `comm == "sleep"`. If the host machine has unrelated `sleep` processes running, the assertion could be confused — in practice this is rare on test machines, but a more rigorous version would track the specific PID returned by the launch.
