# Issue 7: Properly support HiDPI displays

<https://git.armeafamily.com/albert/shepherd-launcher/issues/7>

## Goal

Let an admin configure `output * scale N` (or any other site-local Sway
tweak) without it being clobbered next time `shepherd install sway-config`
runs. The issue identifies HiDPI scale as the motivating use case but the
mechanism should be general.

## Approach

Sway already supports config drop-ins via the `include <path>` directive,
which uses `wordexp(3)` for glob expansion (see `man 5 sway`). An empty
glob is treated as a no-op, so the mechanism degrades cleanly when no
override files are present.

Add `include /etc/sway/shepherd.conf.d/*.conf` to the shipped `sway.conf`
and have `shepherd install sway-config` create the empty drop-in directory
alongside the regenerated config. The installer never touches the
directory's contents on subsequent re-installs because `ensure_dir` is a
no-op for an existing directory and we never `rm` from `shepherd.conf.d/`.

### Why not put scale in `config.toml` and call `swaymsg`?

That would funnel display config through shepherdd → swaymsg, which adds
ordering concerns (shepherdd starts before sway is fully up in some
init paths) and a Rust-side schema for what is fundamentally a Sway
concern. The `include` approach keeps Sway config in Sway and matches the
pattern already used by upstream sway packages (Arch's default config
includes `/etc/sway/config.d/*`).

### Why hardcode the `/etc/sway/...` path in dev's `sway.conf`?

`sway.conf` is shipped verbatim in dev mode and `sed`-rewritten only for
binary paths during install. The include path doesn't need rewriting:
- In dev, the directory typically does not exist, so the glob silently
  matches nothing.
- In prod, the directory is created by the installer.
- A developer who *does* have `/etc/sway/shepherd.conf.d/` on their dev
  machine (because the same machine is also a kiosk target) gets the
  overrides applied to dev too — that's a feature, not a bug.

## Changes

- `sway.conf`: add the `include` directive in the output-configuration
  section with a comment pointing at HiDPI as the motivating example.
- `scripts/lib/install.sh`: declare `SHEPHERD_SWAY_CONFD="shepherd.conf.d"`
  and `ensure_dir` it during `install_sway_config`.
- `docs/INSTALL.md`: document the drop-in directory and show the HiDPI
  one-liner so new operators find it without spelunking through
  `sway.conf`.

No Rust changes; nothing to test in the Rust suite.
