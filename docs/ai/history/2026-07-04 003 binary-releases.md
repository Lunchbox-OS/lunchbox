>

## Issue #82: "Binary releases"

> We should make actual tags/releases with `.deb`s and `.apk`s for ease of
> installation. The binaries should be built in CI. This depends on the unified
> versioning system (#83).

#83 has landed (`VERSION` file + `shepherd version set/check`), so the
dependency is satisfied.

## Goals

- A push of a `vX.Y.Z` tag produces a Forgejo release with:
  - `shepherd-launcher_X.Y.Z_amd64.deb` — the full kiosk install.
  - one signed `.apk` per Android app module (today: `companion`).
  - `SHA256SUMS` over all attached artifacts.
- Everything builds in CI on the existing pre-baked images. No new toolchains.
- The package layout is **not** re-encoded anywhere; it is derived from the same
  `scripts/lib/install.sh` that a from-source install already uses.

## Non-goals (deferred)

- arm64 `.deb` (cross-compiling GTK4 + bundled rusqlite + the BPF helper is its
  own project). Filed as a follow-up.
- GPG-signed `.deb` / a hosted APT repository. We ship `SHA256SUMS` now; signing
  and a repo come once there's a signing key and appetite.
- Publishing the APK anywhere but Forgejo releases (no F-Droid/Play).

## What a release must contain

A real install is more than the workspace binaries. From `install.sh`, the
`.deb` must reproduce this tree:

| Payload | Destination | Source |
|---|---|---|
| 8 workspace binaries | `/usr/bin` | `SHEPHERD_BINARIES` (`build.sh`) |
| `shepherd-firewall-helper` | `/usr/libexec/` (fixed path) | firewall crate — needs nightly + bpf-linker |
| polkit policy + rule | `/usr/share/polkit-1/actions`, `/etc/polkit-1/rules.d` | `dist/polkit/` |
| udev rule | `/etc/udev/rules.d/` | `dist/udev/` |
| sway config + drop-in dir | `/etc/sway/shepherd.conf{,.d}` | `sway.conf` (path-rewritten) |
| wayland-session desktop entry | `/usr/share/wayland-sessions/` | generated by `install_desktop_entry` |
| webui | embedded into `shepherdd` | `rust-embed` (npm build runs before cargo) |

Per-user config (`~/.config/shepherd/`) is **not** packaged — that stays a
first-run/admin step (`shepherd install config --user …`). The firewall helper
goes to a fixed `/usr/libexec` path regardless of prefix, because the polkit
`.policy` references it by absolute path.

The `.apk` is the `companion-android` Gradle project — arch-independent Kotlin.

## Key leverage point: `install.sh` is already `DESTDIR`-aware

`install_firewall` / `install_udev` explicitly skip host mutation
(`groupadd`, `usermod`, `udevadm`/`polkit` reload) when `DESTDIR` is set — the
code was written with packaging in mind. **The install layout is therefore
already single-sourced.** We must not duplicate it in packaging metadata.

This is why we do **not** use `cargo-deb`: it is per-crate and Cargo-metadata
driven, and cannot express `/usr/libexec` + polkit + udev + sway assets without
re-encoding what `install.sh` already knows. A staged `dpkg-deb` that drives
`install.sh` with `DESTDIR` keeps the layout in exactly one place.

## Design

### 1. `shepherd package deb` — staged `dpkg-deb`

New library `scripts/lib/package.sh`, dispatched from `scripts/shepherd` as
`shepherd package deb`. It:

1. `./scripts/shepherd build --release` — builds the whole workspace, including
   `shepherd-firewall-helper` (not in `SHEPHERD_BINARIES`, so the package build
   must not rely on that array for the helper).
2. Stages the install tree into a build root, reusing `install.sh` verbatim:
   ```sh
   stage="$(mktemp -d)"
   DESTDIR="$stage" ./scripts/shepherd install bins --prefix /usr
   DESTDIR="$stage" ./scripts/shepherd install firewall          # helper + polkit assets, no host mutation
   DESTDIR="$stage" ./scripts/shepherd install sway-config --prefix /usr
   DESTDIR="$stage" ./scripts/shepherd install desktop-entry --prefix /usr
   DESTDIR="$stage" ./scripts/shepherd install udev
   ```
   Under `DESTDIR`, each of these skips group/udev/polkit host mutation.
3. Generates `DEBIAN/` control files:
   - **`control`** — `Version` from `VERSION`; `Architecture: amd64`;
     `Depends:` generated by stripping comments/blanks from
     `scripts/deps/run.pkgs` and joining with `, ` (so runtime deps stay
     single-sourced too — `sway`, `mpv`, `bluez`, `brightnessctl`,
     `python3-venv`, the `libgtk-4-1`/`libadwaita-1-0`/`libgtk4-layer-shell0`
     runtime libs, …). Optionally augment with `${shlibs:Depends}` via
     `dpkg-shlibdeps` later; the `run.pkgs` list is sufficient to start.
   - **`conffiles`** — the admin-editable files so `dpkg` preserves local edits
     on upgrade: `/etc/sway/shepherd.conf`, `/etc/polkit-1/rules.d/50-shepherd-firewall.rules`.
     (`/etc/sway/shepherd.conf.d/*` is a user drop-in dir, left unmanaged.)
   - **maintainer scripts** — exactly the host-mutating steps `install.sh`
     guards out under `DESTDIR`:
     - `postinst`: `groupadd --system shepherd-firewall` (idempotent),
       `udevadm control --reload-rules && udevadm trigger /dev/uinput`,
       `systemctl reload polkit || systemctl restart polkit` (best-effort).
     - `postrm` (`remove`/`purge`): reload udev/polkit; leave the system group
       in place (other installs / leftover files may reference it).
4. `dpkg-deb --root-owner-group --build "$stage" "$out/shepherd-launcher_${VERSION}_amd64.deb"`.

This is shellcheck-linted like the rest of `scripts/` and buildable locally
(`shepherd package deb`) without CI — the CI job is a thin wrapper.

> **Note on group membership.** `install all` adds the *kiosk user* to
> `input`/`video`/`bluetooth`/`shepherd-firewall`. A distro package can't know
> which user that is, so the `.deb` does **not** do per-user `usermod`. That
> stays an explicit post-install admin step. This is documented in the release
> notes / `INSTALL.md` "installing from the .deb" section (follow-up).

### 2. `release.yml` — tag-driven release workflow

Separate from `ci.yml`: different trigger, different permissions, different
lifecycle.

- **Trigger:** `push: tags: ['v*']`.
- **`guard` job:** verifies `${GITHUB_REF_NAME#v}` equals `VERSION` and runs
  `shepherd version check`. Reuses the #83 harmony guarantee so a mistagged
  release fails loudly instead of shipping mismatched artifacts. All other jobs
  `need` it.
- **`image` / `image-android` jobs:** mirror `ci.yml` — compute the
  content-hash image ref and build-if-missing. See the DRY note below.
- **`deb` job:** runs in the base `image` container; `shepherd package deb`;
  uploads the `.deb` as a workflow artifact.
- **`apk` job:** **matrix over Android modules** (fan-out for #3). Runs in the
  `image-android` container; `./gradlew :<module>:assembleRelease` with a
  signing config fed from secrets; uploads each APK as an artifact. Adding
  `shepherd-media-android` later is one matrix row.
- **`publish` job:** downloads all artifacts, computes `SHA256SUMS`, then uses
  the **Forgejo API** (`${{ github.server_url }}/api/v1/repos/${{ github.repository }}/releases`)
  with a `FORGEJO_TOKEN` secret to create the release and upload every asset.
  Using the raw API keeps the workflow free of third-party action availability
  assumptions on the self-hosted runner.

**Release flow:** `shepherd version set X.Y.Z` → commit → `git tag -a vX.Y.Z`
→ `git push --tags`. CI does the rest.

### 3. APK signing & `versionCode` (needs a Gradle change)

`versionCode` is currently hardcoded `1` in `app/build.gradle.kts`. Every
in-place update needs a **monotonic** code, so derive it from `VERSION` the same
way `versionName` already is:

```kotlin
val v = shepherdVersion.substringBefore('-').split('.')   // strip any -prerelease
versionCode = v[0].toInt() * 10000 + v[1].toInt() * 100 + v[2].toInt()
```

Signing: a release keystore lives in CI secrets (base64 keystore +
store/key passwords + alias). A guarded `signingConfigs.release` reads them from
the environment and falls back to debug-signing when they're absent (so local
`assembleRelease` still works):

```kotlin
val ksPath = System.getenv("SHEPHERD_KEYSTORE_FILE")
signingConfigs {
    if (ksPath != null) create("release") {
        storeFile = file(ksPath)
        storePassword = System.getenv("SHEPHERD_KEYSTORE_PASSWORD")
        keyAlias = System.getenv("SHEPHERD_KEY_ALIAS")
        keyPassword = System.getenv("SHEPHERD_KEY_PASSWORD")
    }
}
buildTypes {
    release {
        signingConfig = signingConfigs.findByName("release")
            ?: signingConfigs.getByName("debug")
        // …existing minify/proguard config…
    }
}
```

The `apk` job base64-decodes `secrets.SHEPHERD_KEYSTORE_B64` to a file and
exports `SHEPHERD_KEYSTORE_FILE` + passwords before `assembleRelease`.

## Required CI secrets

| Secret | Used by | Purpose |
|---|---|---|
| `REGISTRY_TOKEN` | image / container pulls | already exists (see `ci.yml`) |
| `FORGEJO_TOKEN` | `publish` | create release + upload assets (repo write) |
| `SHEPHERD_KEYSTORE_B64` | `apk` | base64 of the release keystore |
| `SHEPHERD_KEYSTORE_PASSWORD` | `apk` | keystore password |
| `SHEPHERD_KEY_ALIAS` | `apk` | signing key alias |
| `SHEPHERD_KEY_PASSWORD` | `apk` | signing key password |

## Done in follow-up passes

- **DRY on image jobs.** The `image` / `image-android` build-if-missing jobs
  were extracted into a `workflow_call` reusable workflow (`images.yml`) that
  both `ci.yml` and `release.yml` invoke via `uses:` + `secrets: inherit`,
  exposing `base-ref` / `android-ref` outputs. (One caveat: reusable workflows
  require a Forgejo version that supports `workflow_call`; validate on the first
  PR run, since this touches the critical CI path.)
- **PR-time `.deb` smoke build.** `ci.yml` gained a `package` job that runs
  `shepherd package deb` on every push/PR (build only, no publish) so packaging
  breakage is caught before a release tag.
- **`INSTALL.md` section** documenting install-from-`.deb` and the required
  post-install `shepherd install config --user` / `groups --user` steps.
- **yt-dlp guidance** (superseded by the shared admin CLI below). `yt-dlp` isn't
  apt-installed; the from-source path builds it into a venv at
  `/opt/shepherd/ytdlp-venv` via `deps install run` (`install_ytdlp`), which a
  `.deb` user never runs. Rather than keep printing raw commands, this was folded
  into a shared admin CLI.
- **Shared admin CLI (`shepherd-admin`).** Refactored the repo-bound admin tasks
  so they run from both the source tree and a `.deb` install:
  - New `scripts/lib/admin.sh` holds the repo-independent tasks: yt-dlp
    (moved out of `deps.sh`), `apps install steam|chrome` (Steam via
    Canonical's snap — what `type="steam"` drives — Chrome via the Flathub
    flatpak), and
    `setup-user` (config + all group memberships, reusing `install_config` /
    a new shared `add_user_to_groups`). `harden.sh` / `bluetooth.sh` were
    already repo-independent.
  - New `scripts/shepherd-admin` entrypoint resolves its libs from a sibling
    `lib/` dir and detects source-vs-packaged layout, exporting
    `SHEPHERD_DATA_DIR` (`get_data_dir` in `common.sh`) so example configs
    resolve to the repo root or `/usr/share/shepherd` accordingly. It omits the
    build/package/dev machinery that needs a source tree.
  - `scripts/shepherd` sources `admin.sh` and gained `apps` / `setup-user` for
    parity; the tasks share one implementation.
  - The `.deb` ships `scripts/lib/*.sh` + `shepherd-admin` under
    `/usr/lib/shepherd/`, symlinked to `/usr/bin/shepherd-admin`, plus `VERSION`
    in the data dir. The postinst guidance collapsed to `shepherd-admin
    setup-user USER` / `yt-dlp install`, and `INSTALL.md` follows suit.
- **`shepherd-media-android` (#72)** — added as a second `apk` matrix row. Its
  Gradle `assembleRelease` cross-compiles a Rust cdylib via cargo-ndk for both
  packaged ABIs (arm64-v8a + armeabi-v7a), so the row carries a `rust: true`
  flag that gates cargo-ndk/target/NDK setup that the pure-Kotlin companion row
  skips. Its `build.gradle.kts` was also given the VERSION-derived
  `versionCode`/`versionName` and the guarded release signing config, matching
  companion.
